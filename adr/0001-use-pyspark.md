# ADR 0001: Apache Sparkによる分散処理基盤の導入と環境構築

## コンテキスト (Context)
- 1,500次元を超える高次元なスペクトルデータを取り扱う際、将来的なデータ量の増大（スケーラビリティ）を見越し、単一マシンのメモリに依存しない処理基盤が必要となった。
- 実行環境の差異（OS、Java、ライブラリのバージョン）による「私の環境では動く」問題を解消し、チーム開発における再現性を確保する必要があった。

## 意思決定 (Decision)
1. **データエンジン**: **Apache Spark (PySpark) 3.5.0** を採用。ベクトル化された特徴量生成（Pandas UDF）を可能にする。
2. **インフラ**: **Docker / Docker Compose** を採用し、Master x1, Worker x2 の疑似分散環境をローカルに構築。
3. **実行環境**: **Java 21 (OpenJDK)** を採用。Debian (Python:3.11-slim) 環境下での最新LTSとしての安定性と Spark 3.5.0 との互換性を重視。

## ステータス (Status)
Accepted (2026-04-05)

## 影響 (Consequences)
- **メリット**: 数万件〜数百万件のデータに対しても、ノード（Worker）を追加するだけでスケール可能になった。
- **メリット**: Docker により、AWS EMR 等のクラウド環境への移行が容易になった。
- **トレードオフ**: ローカル環境において Docker Desktop の起動コストと、ビルド時の依存関係管理（Java等のインストール）の手間が発生する。
