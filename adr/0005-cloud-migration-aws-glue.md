# ADR 0005: AWS Glue採用による計算基盤のクラウド移行とスケールアウト

## ステータス
提案中（2026-04-13 次段階のロードマップとして定義）

## コンテキスト
ADR 0004においてローカルマシンの物理限界（24コア）をフル活用する最適化を完遂したが、1,500次元を超えるスペクトルデータや将来的なビッグデータ、および複数モデルの並列検証を想定した場合、オンプレミス（Local Docker）環境では以下の限界が顕在化している。

1. **リソースの物理的上限**: 24コア以上の計算資源を確保できず、処理の更なる高速化が困難。
2. **リソース競合**: 特徴量生成および学習実行中、ホストマシンの全リソースを占有するため、他の開発・解析タスクとの並行作業が著しく制限される。

## 検討される課題
* **リソースの弾力性 (Elasticity)**: 処理負荷に応じて動的に計算リソース（DPU）を増減させ、ボトルネックを解消したい。
* **データの永続性と共有**: ローカルディスク依存から脱却し、イレブンナインの耐久性を持つ S3 への移行によるデータ堅牢性の確保。
* **運用コストの最適化**: 24コア環境を常時維持するコスト（電力・設備）に対し、実行時のみ課金されるクラウドモデルの経済的優位性を検証する。

## 意思決定（戦略的アプローチ）
1. **AWS Glue Interactive Sessions の採用**:
   サーバーレスな Spark 環境を採用することで、インフラ管理コスト（EC2のプロビジョニング等）を排除し、必要な時だけ巨大な計算リソースを確保する。
2. **S3-Centric Architecture への転換**:
   すべての入出力データを S3 経由に統一。データパイプラインの起点をクラウド化し、将来的な SageMaker 等の AI サービスとの連携を容易にする。
3. **ローカル環境からの「シームレスな移植性 (Portability)」の維持**:
   ADR 0004 で確立した JVM チューニング（Java 21 対応）や依存ライブラリの知見を Glue のカスタム設定に注入し、ローカルで検証済みのロジックを最小限の修正でクラウドへデプロイする。

## 帰結
### メリット
* **無限のスケール**: DPU（Data Processing Units）の調整により、ローカルの24コアを遥かに超える並列処理が可能になる。
* **コスト効率**: 実行時のみ課金されるため、大規模な実験を行う際もトータルコストを最適化できる。
* **開発体験の向上**: 重い処理をクラウドへオフロードすることで、ローカルマシンでのマルチタスクが可能になる。

### デメリット / リスク
* **クラウドコストの管理**: 意図しないセッション維持による課金リスク。
* **データ転送コスト**: ローカルから S3 への初回データアップロードに時間を要する。
